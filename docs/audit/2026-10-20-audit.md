## 4. Proposed curriculum

The curriculum is specified fully in [`CURRICULUM.md`](../CURRICULUM.md). In summary:

- **Part 0** — Orientation, prerequisites, environment setup, first deterministic context experiment.
- **Part I** — Foundations: the discipline, tokens and context windows, anatomy of context, failure diagnosis.
- **Part II** — Knowledge sources: corpus design, ingestion, chunking, indexing, retrieval, provenance/freshness/access.
- **Part III** — Dynamic construction: lifecycle, selection, budgeting, ordering, compression, progressive disclosure, caching.
- **Part IV** — History, persistent memory, and structured state.
- **Part V** — Tools, multi-step workflows, multi-agent isolation, multimodal context.
- **Part VI** — Security, privacy, multi-tenancy, governance.
- **Part VII** — Evaluation, test-driven context engineering, observability.
- **Part VIII** — Reliability, performance, deployment, provider comparisons.
- **Part IX** — Capstone: reference implementation and portfolio projects.

A single longitudinal example — a synthetic corporate knowledge base for the fictional company **Nimbus Dynamics** — evolves across the entire curriculum so learners follow one system from raw documents to a secure, evaluated assistant.

## 5. Architecture decisions

- **Language/runtime:** Python 3.10+ (tested on 3.12), standard library only for all core implementations. Optional adapters (exact tokenizers, embedding models, provider APIs) are isolated behind interfaces so no chapter depends on paid access.
- **Test strategy:** `unittest` (zero dependencies, runs via `python -m unittest discover`); deterministic tests for deterministic components; model-dependent behavior is always labeled and kept optional.
- **Layout:** `chapters/` (notes by part), `labs/`, `projects/` (beginner → capstone), `src/context_engineering/` (reference library), `tests/`, `datasets/synthetic/`, `docs/`, `glossary/`, `references/`.
- **Security posture:** synthetic data only; trust boundaries encoded in the library (trusted instructions vs. untrusted retrieved content); access filtering happens *before* context assembly; logs are redacted by default; no secrets are ever committed.

## 6. Concerns and deferred decisions

- **License:** none exists. Per the master prompt, a license is a legal decision that belongs to the repository owner; none is added silently. The owner should add one (MIT or Apache-2.0 are common defaults for educational code) — tracked in `ROADMAP.md`.
- **Credential hygiene:** the repository is configured for token-based push access using a credential store outside the repository. No token, key, or personal data appears in any tracked file; a leak check runs before every commit.
- **Provider-specific claims:** provider APIs (context caching, prompt caching, tokenizers) change frequently. Such claims are dated "reviewed 2026-10-20" and framed as verify-before-rely, with core concepts taught provider-neutrally.
